# Framework Cloud prose

Adapted from Erik’s `agent-skills/skills/writing/SKILL.md`. These rules apply
to product copy and project prose. Preserve technical meaning and behavior.

## Headings and labels

Use descriptive nouns or short noun phrases. Name the subject directly.
Use sentence case. Avoid questions, conversational prompts, and full sentences.

| Avoid | Use |
|---|---|
| Where published notebooks go | Artifact storage |
| What you manage | Server administration |
| What a self-hosted server includes | Server features |
| Who can open this artifact? | Reader access |
| What changed | Version notes |
| Which language do you use most? | Primary language |
| What the project is made of | Project components |

Buttons and action links use direct verbs: Save changes, Copy link, Create
project. Toggle labels can name the behavior: Git initialization, Agent files.
Keep confirmation consequences explicit in the body and action button.

## Sentences

Write short, terse sentences. Make one useful claim per sentence. Use concrete
subjects and active verbs. Remove setup phrases, rhetorical questions, reader
flattery, sales flourishes, and trailing commentary.

Use enough detail to explain a setting’s effect. Retain limitations, password
requirements, version behavior, and destructive consequences. Brevity must not
hide behavior or turn documentation into cryptic fragments.

Avoid antithesis such as “X, not Y,” dramatic reversals, slogans, invented
metaphors, and self-approving explanations. Prefer periods to em dashes and
semicolons. Use American English and the Oxford comma.

## Product terms

- Artifact: a published figure, table, model, data file, document, or other output.
- Notebook: a notebook specifically. Do not use it for every artifact.
- Collection: a group of artifacts with selected or latest versions.
- Report: text and artifacts assembled in the editor.
- Blueprint: a reusable project setup.
- Project: the settings and context linking research files and artifacts.

Preserve user-authored titles, descriptions, report content, skill instructions,
and imported documentation. Audit application-owned copy, including dynamic
strings and guide navigation. Keep accessible labels meaningful.

## Review

Read each heading without its body. It should identify the section. Check
nearby help text for repeated explanations. Verify terms against actual behavior.
Check matching guide links and anchors after renaming documentation headings.
